# BUG-038 — C++ EH landing pad: loader resumes at RtlUnwindEx's TargetIp, but
# llvm-mingw's libunwind passes ControlPc as a PLACEHOLDER there

**Status:** OPEN (REGISTERED 2026-10-15, CONTINUE #7) — next task
**Priority:** P0 (blocks t08/G2 C++ EH acceptance)
**Discovered:** immediately after BUG-037's fix, running t08

## Symptom

After BUG-037's fix, t08's first throw completes the ENTIRE 4-frame walk and
the intermediate cleanup walk correctly, then the loader resumes and dies:

```
[CRASH] Signal 4 (SIGILL) at RIP=0x140001c85  RVA=0x1c85 (inside loaded PE)
  RAX=0x32ec270 (exception object) RSP=0x7fffe5144ff0 (correct body RSP)
  RBP=0x7fffe5145070 (correct FP)
RtlUnwindEx: FP frame reg=5 off=8 -> body RSP=0x7fffe5144ff0   (correct)
RtlUnwindEx: target_func RVA=0x1470 alloc_total=0x188          (correct)
RtlUnwindEx(target_frame=0x7fffe5145070, target_ip=0x140001c83, ...)
```

RIP=0x140001c83 is the MIDDLE of `call 0x140002420` (bytes 0x1c7f..0x1c83);
execution limps to 0x1c85 and hits SIGILL.

## Ground truth (all evidence in hand)

1. The true landing pad for the throw region comes from the LSDA at
   UI(0x50458)+36: `scripts/bug037_lsda_parse.py` fully decodes it —
   header `ff 00 <ttype uleb 476> 01 <cs len 429>`, 73 entries; the entry
   covering the throw call `[0x806,0x829)` has **lp=0x82d → VA 0x1c9d**
   (`mov rbx,rax`, the catch block) with action=5 (the catch filter).
   No entry anywhere has lp=0x813 (0x1c83).
2. The personality inside t08 is the libunwind/libc++abi stack: the handler
   thunk at 0x131b0 calls `_GCC_specific_handler` (Unwind-seh.cpp), which
   for phase-1 HANDLER_FOUND executes
   `RtlUnwindEx(frame, (PVOID)disp->ControlPc, ms_exc, exc, ms_ctx, hist)`
   — **TargetIp is a placeholder (= ControlPc), NOT the landing pad**
   (llvm-project libunwind/src/Unwind-seh.cpp, release/19.x, ~L151).
   GCC's libgcc unwind-seh.c by contrast passes `gcc_context.ra` = the real
   cached landing pad — which is why the UPX G1 flow (GCC-style resume
   command 0x21474343 with param[2]=LP) worked.
3. The real landing pad travels in the exception object's **barrier cache**
   (libcxxabi `save_results_to_barrier_cache`: `bitpattern[3] = landingPad`)
   and is installed at TARGET-FRAME DELIVERY: when the dispatcher calls the
   personality again with `ExceptionFlags |= EXCEPTION_TARGET_UNWIND (0x4)`
   and `ExceptionInformation[1] == target_frame`, `_GCC_specific_handler`
   routes to phase-2 `CLEANUP|HANDLER_FRAME`; libcxxabi restores the cache
   and `set_registers()` executes `_Unwind_SetIP(context, results.landingPad)`
   — writing the LP into `disp->ContextRecord->Rip` — and returns
   ExceptionExecuteHandler (4). The OS then installs that context.
4. Our loader's `dc.ControlPc = current_rip - 1` (loader.c ~L1727) and the
   `ctx.Rip -= 1` adjustment (~L1741) also feed the placeholder math; the
   personality's `scan_eh_tab` does `ip = _Unwind_GetIP(context) - 1` itself
   (libcxxabi cxa_personality.cpp ~L647), so with our already-decremented
   ControlPc the lookup ip = return-2. For t08's wide call-site region
   [0x806,0x829) this still selects the right entry — but the double
   decrement must be audited against real Windows (ControlPc = full return
   address; the personality subtracts 1).

## Fix plan (evidence-first)

1. In `mw_RtlUnwindEx`, after the intermediate cleanup walk reaches the
   target frame, perform the OS-faithful TARGET-FRAME DELIVERY before any
   resume: call the target frame's personality with
   `er.ExceptionFlags |= 0x2|0x4`, `ExceptionInformation[1] = tgt_frame`,
   `NumberParameters = 4`, `dc.ContextRecord = &resume_ctx`,
   `dc.TargetIp = tgt_ip`, `dc.EstablisherFrame = tgt_frame`.
2. Honor the personality's result: if it returns 4 (ExceptionExecuteHandler)
   or has modified `resume_ctx.Rip`, resume with that context (Rip = real LP
   0x1c9d, Rsp = body RSP, Rax = exception object, Rdx = selector).
3. Keep the GCC-style path intact: GCC's personality answers target delivery
   with `ContextRecord->Rdx = Info[3]; return ContinueSearch` and the resume
   still uses TargetIp (= its real cached LP) — so UPX G1 must stay green.
4. Verify: t08 prints `t08: PASS` exit 0, 3/3 deterministic; regression
   12/12; UPX G1 gate; full sweep 11/12 (t09 = API frontier).
