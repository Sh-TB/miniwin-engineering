# BUG-060 — InitOnceExecuteOnce global mutex self-deadlock on nested callbacks

**Status:** CLOSED (TESTED) — 2026-10-17, wave W4
**Found by:** curl.exe hang (futex_wait on a function-local mutex)
**Files:** src/loader/loader.c

## Root cause
InitOnceExecuteOnce serialized ALL once-controls with one static mutex.
curl's UCRT init runs nested InitOnce callbacks (locale init inside another
once callback) on the same thread → same-thread mutex deadlock.

## Fix
Windows-faithful state machine inside the once-control itself:
0=init, 1=in-progress (CAS transition), 2=complete; failed callbacks roll
back to 0; racing waiters spin on completion (single-team guests).

## Verification
curl --version no longer hangs (new frontier is the UCRT 0x100000000-tagged
state pointer crash, registered as OPENSRC-CURL-1).
