# BUG-026 — g_cap_rip capture operand wrong in mw_RaiseException naked stub

**Status:** CLOSED — VERIFIED FIXED (2026-10-14, commit `BUG-026: restore g_cap_rip capture operand`)
**Priority:** P0 (acceptance path blocker)
**Discovered:** TASK-004 forensics (2026-10-14, probe-proven, forensics §1 F8)
**Fixed:** 2026-10-14, single-operand change in `src/loader/loader.c` mw_RaiseException stub

## Symptom (pre-fix)
- Regression 10/12: "RUNTIME_FUNCTION lookup NOT found" + exit 134 (SIGABRT) instead of 139.
- UPX acceptance: no output; `terminate called after throwing an instance of 'unsigned long long'`; exit 134.
- Trace: every RaiseException dispatch ended at `Frame[0]: RIP outside PE — walk ends` because CONTEXT.Rip was a **stack address**.

## Root cause
The naked stub's "Copy to globals" block loaded `g_cap_rip` from the wrong slot:

```asm
movq 0x58(%rsp), %rax    ; stray reload (rsp_entry)
movq 0x00(%rsp), %rax    ; saved rsp_entry — a stack ADDRESS
movq %rax, g_cap_rip(%rip)
```

The stub had already saved the true return address into slot `[rsp+0x08]`
(`movq (%rax),%rbx; movq %rbx,0x08(%rsp)`) but then never used it. Regression
introduced during the fdb939c-era asm edits, synced through d36fc5e; the correct
form survives in `src/loader/loader.c.exp_next2_backup` L842-843.

## Fix
`movq 0x08(%rsp), %rax` immediately before `movq %rax, g_cap_rip(%rip)`
(stray `0x58` reload deleted). One operand; nothing else touched.

## Verification (post-fix, fresh build `c8472d04…`)
- Regression suite: **12/12 PASS** (tests 8 & 10 pass again — `evidence/master/bug026/regression_12of12.txt`).
- UPX: walk now completes 4 frames, personality at Frame[3] is called and calls
  real `RtlUnwindEx(TargetIp=0x4dcd24)`; exit changed 134→139 (terminate path gone).
- New, distinct post-unwind failure (RSP+8 / RDX selector at landing pad) is a
  separate defect: **BUG-027** — see `docs/master/experiments/EXP-036-bug026-gcap-rip-fix-live-rerun.md` §4.

## Side observation (out of scope, recorded)

(comments "save PE RCX/RDX/R8/R9") do not match the current frame layout and do
not exist in `exp_next2_backup`; benign leftover of an older stub variant.
