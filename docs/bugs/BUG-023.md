# BUG-023: Missing GCC C++ Exception Unwinding Support

## Status
ACTIVE

## Severity
CRITICAL — blocks all C++ exception handling, causes abort() on throw

## Summary
UPX execution reaches C++ exception handling but cannot unwind because
`RtlLookupFunctionEntry` returns NULL and `RtlVirtualUnwind` is a no-op.
The GCC runtime then falls back to `RaiseException(0x20474343)` and
ultimately calls `abort()`.

### Exception Code Analysis
- `0x20474343` = bytes `43 43 47 20` = "CCG " (little-endian)
- This is a GCC internal exception code, NOT the standard MSVC C++ code
  `0xE0434352` ("RCC\xE0")
- Indicates the GCC unwinder (`_Unwind_RaiseException` from libgcc) is
  attempting to throw but cannot find function entries

## Root Cause

### Primary: RtlLookupFunctionEntry returns NULL
```c
// Current stub (line 681-684)
__attribute__((ms_abi)) void* mw_RtlLookupFunctionEntry(uint64_t addr, void* base, void* history) {
    MW_TRACE("RtlLookupFunctionEntry(addr=0x%lx)", addr);
    return NULL;  // <-- ALWAYS RETURNS NULL
}
```
The GCC unwinder calls this to find the RUNTIME_FUNCTION for the current
PC. Returning NULL causes unwinding to fail immediately.

### Secondary: RtlVirtualUnwind is a no-op
```c
// Current stub (line 690-694)
__attribute__((ms_abi)) int mw_RtlVirtualUnwind(uint32_t code, uint64_t addr, void* info,
    void* ctx, void* data, void* disp) {
    MW_TRACE("RtlVirtualUnwind()");
    return 0;  // <-- DOES NOTHING
}
```
Even if RtlLookupFunctionEntry worked, this function must:
1. Parse UNWIND_INFO to find the language-specific handler
2. Return the handler address and LSDA pointer
3. Simulate unwind codes to restore non-volatile registers
4. Calculate the establisher frame

### Tertiary: UNWIND_INFO flag parsing bug in RaiseException
```c
// Line 621 (WRONG)
uint8_t ui_flags = ui[1] & 0x1F;  // ui[1] is SizeOfProlog, not flags!

// Correct per x64 PE spec:
// Version = ui[0] & 0x07
// Flags   = (ui[0] >> 3) & 0x03
```
The flags are in byte 0, not byte 1.

### Quaternary: Hardcoded .pdata address
```c
// Line 607-608
uint32_t pdata_rva = 0x1f8000;   // Hardcoded for UPX only
uint32_t pdata_size = 0x8e08;    // Hardcoded for UPX only
```
Should read from the Exception Data Directory (DD_EXCEPTION = index 3),
which already correctly points to VA=0x1f8000, Size=0x8e08.

### Quaternary: .pdata not stored globally
The .pdata location is only available inside `mw_RaiseException` via
hardcoded values. `RtlLookupFunctionEntry` has no access to it.

## Required Fixes

### 1. Store .pdata info globally (from Exception Data Directory)
In `load_pe()`, after section mapping:
```c
if (num_dd > DD_EXCEPTION && dd[DD_EXCEPTION].VirtualAddress != 0) {
    g_pdata_rva = dd[DD_EXCEPTION].VirtualAddress;
    g_pdata_size = dd[DD_EXCEPTION].Size;
    g_num_rt_functions = g_pdata_size / 12;
}
```

### 2. Implement RtlLookupFunctionEntry
- Binary search through .pdata RUNTIME_FUNCTION entries
- Input: control_pc (absolute address)
- Output: pointer to RUNTIME_FUNCTION in mapped image
- Also set *image_base output parameter

### 3. Implement RtlVirtualUnwind
- Parse UNWIND_INFO with correct bit extraction:
  - `version = ui[0] & 0x07`
  - `flags = (ui[0] >> 3) & 0x03`
- Find language-specific handler RVA
- Return handler address and LSDA via output parameters
- Simulate unwind codes (opcodes 0-8) for register restoration
- Calculate establisher frame

### 4. Fix UNWIND_INFO parsing in RaiseException
- Use correct flag extraction from byte 0, not byte 1
- Use global .pdata info instead of hardcoded values

### 5. Add RaiseException instrumentation
When RaiseException occurs, log:
- Exception code
- Return address (RIP)
- Stack pointer (RSP)
- Current function RVA
- Corresponding RUNTIME_FUNCTION entry (if found)

### UNWIND_INFO Format (confirmed from binary)
```
Byte 0: [Flags(5)] [Version(3)]  -- Version=1 for all entries
Byte 1: SizeOfProlog
Byte 2: CountOfCodes
Byte 3: [FrameOffset(4)] [FrameRegister(4)]
Bytes 4..: UNWIND_CODE entries (2 bytes each)
Then (aligned to 4): Handler RVA (4 bytes) if EHANDLER/UHANDLER flag set
Then: Language-specific data (LSDA)
```
