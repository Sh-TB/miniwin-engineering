# BUG-049 — WIN32_FIND_DATAW layout violation + FindFirst contract break

**Status:** CLOSED (TESTED) — 2026-10-17, wave W1
**Found by:** TASK-OPENSRC-7ZIP corpus preparation (7za.exe directory ops)
**Files:** src/loader/loader.c (find family, single block rewrite)

## Symptom
`fill_find_data` wrote `cFileName` at offset +68 and the 64-bit file size at
+52/+56. The real x64 WIN32_FIND_DATAW (592 bytes) is:

| field | offset | size |
|---|---|---|
| dwFileAttributes | 0 | 4 |
| ftCreationTime | 4 | 8 |
| ftLastAccessTime | 12 | 8 |
| ftLastWriteTime | 20 | 8 |
| nFileSizeHigh | 28 | 4 |
| nFileSizeLow | 32 | 4 |
| dwReserved0 | 36 | 4 |
| dwReserved1 | 40 | 4 |
| cFileName[260] | 44 | 520 |
| cAlternateFileName[14] | 564 | 28 |

Any guest reading the name (from +44) or the size (from +28/+32) received
garbage. The old code also zeroed times and mis-flagged attributes.

## Second half: enumeration contract
Windows `FindFirstFileW/FindFirstFileExW` **return the first match and fill
the caller's data buffer**; `FindNextFileW` continues from the second entry.
The old `mw_FindFirstFileExW` opened the directory and returned a handle
WITHOUT filling data and without checking that anything matched, relying on
the guest calling FindNextFileW first. Guests that inspect the first entry
immediately (7-Zip does) saw stale/garbage data.

## Fix (loader.c)
1. `fill_find_data(data, name, st)` rewritten to the exact MS layout,
   times derived from ctime/atime/mtime via the 1601-epoch conversion,
   attributes DIRECTORY/ARCHIVE/HIDDEN(dotfile), name emitted as 2-byte
   UTF-16LE via `w3_utf8_to_utf16le`, cAlternateFileName zeroed.
2. Shared `find_next_match()` walker: fnmatch wildcards (`*`, `?`),
   fstatat for sizes/times, used by both first and next.
3. `find_first_impl()`: non-wildcard patterns stat the exact file and fail
   with ERROR_FILE_NOT_FOUND(2) — Windows fidelity — instead of falling
   through to ERROR_NO_MORE_FILES(18); wildcard patterns with zero matches
   also fail with 2. The first match fills the caller buffer.
4. `FindClose` closes the DIR and frees the slot.
