# BUG-064 — kernel-object layer: events/semaphores/IOCP were instant-success stubs

**Status:** CLOSED — TESTED (2026-10-17)
**Discovered by:** LADDER-009 (lz4.exe 1.10.0) decompress path, after BUG-063
unblocked the banner.

## Symptom chain (one bug lifted, the next surfaced — all measured)

1. `lz4 -d` crashed at RIP=0x5a7ca = hint/name RVA of `CreateIoCompletionPort`
   (unresolved IAT slot still holding ILT contents — BUG-032-local class).
2. After implementing the IOCP trio + RtlAddFunctionTable + __doserrno +
   _vsnprintf: "Error 26 : LZ4F frame decoding could not complete: invalid
   frame", output 0 bytes.
3. Trace + upstream source reading (`lz4 v1.10.0 programs/threadpool.c`,
   fetched per the borrowing policy) showed the full protocol:
   `TPool_submitJob` = wait(jobSlotAvail SEMAPHORE) + ResetEvent + Post(job);
   workers = GQCS(INFINITE) loop calling `((fn)key)(ovl)` and
   SetEvent(allJobsCompleted); `TPool_jobsCompleted` = wait(event).
   Our stubs made `CreateEventA` return `alloc_handle(1)`, SetEvent/Reset a
   no-op, and every wait return 0 instantly — so `TPool_jobsCompleted`
   returned BEFORE any job ran and lz4 exited(26) with lastStatus==1.
4. Fixed events/semaphores with real state: STILL hung — main waited forever
   and the worker was gone. Final root cause: `mw_GetQueuedCompletionStatus`
   never implemented the INFINITE branch (`ms==0xFFFFFFFF` skipped the wait,
   returned FALSE) → lz4's WorkerThread left its `while(GQCS(...))` loop
   immediately → the pool lost its worker → the posted job was never taken.

## Fix (all in loader.c)

- **Events**: `MwKEvent` registry (manual/auto-reset, signaled state,
  mutex+cv). `CreateEventA/W` real; `SetEvent`/`ResetEvent` real;
  auto-reset consumes the signal.
- **Semaphores**: `MwKSem` registry (count/max); `CreateSemaphoreA` real;
  `ReleaseSemaphore` real (saturating, reports previous count).
- **IOCP**: `MwIocp` in-process queue — CreateIoCompletionPort (port create +
  association pass-through), PostQueuedCompletionStatus, and
  GetQueuedCompletionStatus with a real INFINITE branch (pthread_cond_wait)
  plus finite timedwait; ms read as `uint32_t` (a 64-bit read picked dirty
  high bits from the 5th-arg stack slot: 0x7f8dffffffff vs INFINITE).
- **WaitForSingleObject** dispatches thread → event → semaphore → legacy 0;
  **WaitForMultipleObjects** implements wait-all/any over those objects
  (TPool_free waits all worker threads).
- **CloseHandle** releases slots of all kernel-object kinds.
- **MapViewOfFile**: REAL mmap-backed views over the CreateFileMapping
  registry (filemap_lookup → w3fd_from_handle → mmap MAP_SHARED, size-0 →
  EOF), registered for UnmapViewOfFile's munmap.
- New exports: RtlAddFunctionTable (no-op success), __doserrno (state
  pointer), _vsnprintf (msvcrt truncation semantics, guest slot-stream ap).
- Trace now tags every API line with the host thread id ([Txxxx]) — enabled
  the whole diagnosis; kept as a permanent facility.

## Limitations (documented, honest)

- IOCP: queue-only semantics; no real I/O completion packing (fine for lz4's
  worker-pool usage; revisit if a rung relies on I/O-bound completions).
- Events/semaphores: named objects not shared across a namespace; no
  security attributes; WaitForMultipleObjects polls at 10 ms for wait-all.
- Guest threads share TLS slots and have no per-thread CRT init (BUG-062).
