# BUG-027 — mw_RtlUnwindEx resumes the landing pad with wrong RSP (+8) and stale RDX (selector)

**Status:** OPEN — READY (evidence complete, fix designed, not implemented)
**Priority:** P0 (acceptance path blocker — current #1)
**Discovered:** 2026-10-14, live post-BUG-026 trace + static UNWIND_INFO decode
(EXP-036 §4)

## Symptom (post-BUG-026)
- Regression 12/12 (this bug does NOT affect the regression suite).
- UPX: full 4-frame walk completes; Frame[3] personality calls real
  `RtlUnwindEx(target_frame=0x7ffe60f7def8, target_ip=0x4dcd24, ctx=…, exc=0x3bc8320)`;
  PE resumes at RIP=0x4dcd24 with **RSP=0x7ffe60f7deb8**; ~0x170 bytes later
  SIGSEGV at heap RIP=0x2004167 (outside PE). Exit 139.

## Root cause (two coupled sub-defects, one site)

**Site:** `mw_RtlUnwindEx` in `src/loader/loader.c` — the landing-pad CONTEXT is
**synthesized** (RSP = establisher − alloc_total; RAX = ReturnValue) instead of
using the personality-provided state.

1. **RSP +8:** `alloc_total` for function 0xdcbf0 decoded as 0x40; true prologue
   total is **0x48** (PUSH R13, PUSH R12, PUSH RBX, ALLOC_SMALL 0x30 — see
   EXP-036 §4.2). ALLOC_SMALL size decoded as `OpInfo*8` instead of
   `(OpInfo+1)*8` — the same missing-+8 family as forensics N-1 (ALLOC_LARGE),
   now confirmed to also hit ALLOC_SMALL in this copy. Correct resume RSP =
   carried walk context RSP = `0x7ffe60f7deb0` (= establisher − 0x48 = RSP at
   the throw call `call 0x4a95a8` @0x4dcd1f, whose return address IS 0x4dcd24).
2. **RDX selector:** the landing pad `sub rdx,1; jne 0x4dcd8f` requires the C++
   selector in RDX (1 → inline catch body). Our resume state leaves RDX stale
   (−1 observed downstream) — forensics N-4 confirmed live.

**Architectural root:** `mw_RtlUnwindEx` ignores the writable ContextRecord
(r8) and OriginalContext (5th param, [rsp+0x28]) that the MSVC C++ personality
prepares (Rax=exception object, Rdx=selector, Rsp=carried walk RSP).
ADR-008 already targets this; EXP-036 provides the live numbers.

## Fix direction (for the implementing session)
Preferred (correct semantics, ADR-008): resume with the **caller's
ContextRecord** state — Rsp/Rdx/etc. from the context the personality was given
and modified — overriding only `Rip=TargetIp` (and `Rax=ReturnValue` for the
non-C++ path). The alloc_total synthesis disappears from this path.
Minimal alternative (if ContextRecord plumbing is riskier than expected): fix
the ALLOC_SMALL `+8` decode in mw_RtlUnwindEx **and** set RDX from
OriginalContext; but this keeps two synthetic behaviors Windows does not
perform and must be justified in ADR-008 if kept.

## Falsifiable predictions (EXP-036 §7)
- P-1: correct RSP (0x7ffe60f7deb0) + RDX=1 + RAX=0x3bc8320 → catch body runs;
  UPX progresses past 0x4dcd24 (new failure point later, or version output).
- P-2: RSP-only fix with stale RDX → `jne 0x4dcd8f` branch taken — distinct,
  separable outcome.

## Constraints
- Bounds: `mw_RtlUnwindEx` resume-state assembly ONLY. Do NOT touch EH_FIX,
  CXX-EH-FIX, the RaiseException stub, or the walk itself in this task.
- Keep g_unwind_regs restore path consistent with whatever CONTEXT is adopted
  (the naked stub longjmp path consumes it).
- Evidence to produce: fresh UPX trace (landing-pad resume registers), before/
  after regression (must stay 12/12), EXP-037 experiment note.
