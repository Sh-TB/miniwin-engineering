# BUG-051 — GetModuleFileName{A,W} returned the HOST loader path

**Status:** CLOSED (TESTED) — 2026-10-17, wave W2
**Files:** src/loader/loader.c (get_exe_path)

## Symptom
`t13_wide_abi` (new sweep test) checks `wcsstr(module_name, L".exe")`.
GetModuleFileNameW returned `/home/z/.../minwin_loader` — the HOST process
binary, not the guest PE. On Windows a process's module 0 path is its own
executable.

## Root cause
`get_exe_path()` resolved `/proc/self/exe`, which inside the loader process
is the loader itself. The guest path was already available in the global
`g_exe_path` (set from argv[1] in main), but unused by this helper.

## Fix
`get_exe_path()` now returns `g_exe_path` when set (the PE the loader was
told to run), falling back to the old /proc/self/exe probe only when the
loader runs in an environment without it.
