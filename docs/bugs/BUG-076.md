## Analysis

- Pump-off the program exits 0 (x3 deterministic, sweep023 corpus). The crash
  is exclusively on the event-pump path: the guest's synchronous WM_CREATE /
  WM_INITDIALOG work dereferences something the pump path leaves NULL
  (RCX=0x0 at the faulting call).
- Stub call #33 fired just before the crash at guest_rip 0x1400428a3 — the
  EULA-gate region already named in SWEEP-008 (gate @0x140062d1c family).
  Returning 0 from the stub is correct there; the fault is 0x4d72d later.
- Next lever: decode 0x4d72d against the UPX-unpacked image (the dl/ binary
  is packed; static bytes do not match runtime) via a MINWIN_FUNC_MAP export
  for autoruns64, then read the decompile of the faulting function.
