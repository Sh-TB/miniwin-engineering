# BUG-036 — setjmp/longjmp did not honor the Windows x64 jmp_buf contract

**Status:** CLOSED (TESTED, 2026-10-15, EXP-040)
**Priority:** P0 (any error-handling PE)
**Discovered:** appcompat sweep (t06 both checks FAIL; t07 infinite
`longjmp(val=1)` loop, zero output)

## Symptom

- t06: `FAIL: nested longjmp stage`, `FAIL: reuse v=7 counter=1` — the value
  carried correctly but the volatile state/second-pass accounting broke.
- t07: trace showed nothing but repeating `longjmp(val=1)` — the app_error
  handler resumed in the wrong place, re-raised forever.

## Root cause

`mw__setjmp` stored a **glibc sigjmp_buf** inside its own SYSV frame:
1. ms_abi callee-saved registers (RDI, RSI, XMM6-15) are NOT in glibc's save
   set → any PE value live in those registers across setjmp corrupts.
2. Resumption flowed through the loader's frame (siglongjmp → inside
   mw__setjmp → epilogue → back), mis-restoring the boundary state.

## Fix (loader-owned jmp_buf, BUG-036 block)

Uniform 8-byte slot format (mingw x64 jmp_buf = 256 bytes; 30 slots used):
`0..7 rbx,rbp,rdi,rsi,r12-r15 · 8..17 xmm6-15 (2 slots each) · 18 entry rsp ·
19 return address · 29 magic "MWJB"`.
- `mw__setjmp` is **naked** ms_abi asm: rsp at first instruction == entry rsp,
  saves the full ms_abi register file + `[rsp]` (retaddr), returns 0 via
  `xor eax,eax; ret`.
- `mw_longjmp` restores everything, sets `rsp = entry_rsp + 8` (caller's live
  rsp — the +8 pops the saved-retaddr slot and preserves 16-byte alignment),
  puts `val` in EAX, `jmp *retaddr`.

## Verification

- t06 PASS (4-frame longjmp, jmp_buf reuse, volatiles).
- t07 PASS end-to-end: setjmp-based app_error paths raise, handle, and
  continue; journal verification proves the resumed flow.
- Regression 12/12; UPX G1 gate exit 0.
