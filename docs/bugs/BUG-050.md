# BUG-050 — Guest wide-string ABI: glibc 4-byte wchar poisoning

**Status:** CLOSED (TESTED) — 2026-10-17, wave W2
**Found by:** TASK-OPENSRC-7ZIP corpus audit (7za.exe is W-API-heavy); root
class already flagged by BUG-046 (wcslen) — this closes the whole family.
**Files:** src/loader/loader.c (helpers + ~60 sites), tests/appcompat/t13_wide_abi.c (new)

## Root cause
Guest Windows wchar_t is ALWAYS 2 bytes (UTF-16LE). Host glibc wchar_t is 4.
Three poisoning families:
1. **W→A input** (`wcstombs` on guest data): guest "C:\x" = bytes
   `43 00 3A 00 ...`; glibc stops at the embedded NUL -> the conversion
   yields only the FIRST CHARACTER. Every W file API (CreateFileW,
   DeleteFileW, GetFileAttributesW, MoveFileW, _wfopen, SetCurrentDirectoryW,
   FindFirstFileExW, ...) failed on real paths.
2. **A→W emit** (`utf8_to_utf16` = mbstowcs): wrote 4-byte units into guest
   buffers -> every other 2-byte unit was zero garbage (BUG-043 documented
   this for the command line; the same code was still used by ~20 APIs:
   GetModuleFileNameW, GetCurrentDirectoryW, GetTempPathW, env block, ...).
3. **wcs* family** bridged to glibc: 4-byte strides corrupt compare/search/
   copy of 2-byte guest strings (wcschr/wcsrchr/wcsncmp/wcsncpy/wcscat/
   wcscpy/wcsstr/wcsspn/wcscoll/wcsxfrm/wcsnlen/wcscmp/wcstol family/
   wcscpy_s family/wcsrtombs/mbstowcs/wcstombs_s).

## Fix
- `w3_w16_to_utf8z()` / `w3_w16_to_utf8_size()`: NUL-terminated 2-byte to
  UTF-8 conversion with faithful error mapping.
- 38 `wcstombs` input sites + WCTMB fallback + wcstombs_s converted.
- `utf8_to_utf16()` redefined to emit uint16_t UTF-16LE units; 16 terminator
  writes cast to `uint16_t*`; pointer arithmetic fixed (GetFullPathNameW
  *part, _fullpath malloc in 2-byte units, env block now `uint16_t[16384]`).
- Full 2-byte primitives (w16len/cmp/ncmp/cpy/ncpy/cat/chr/rchr/str/spn)
  backing the wcs* exports; strtol-family bridges parse via UTF-8 staging
  with correct end-pointer mapping.

  inputs truncated) — acceptable for current targets, noted for API-017.
