# BUG-001: UPX C++ Exception Handling Crash (SIGABRT)

## Application
- **Binary:** upx_decompressed.exe (UPX 4.2.4 win64, MinGW/GCC compiled)
- **Command:** `miniwin_loader samples/upx_decompressed.exe --version`
- **Hash:** `254ac80deb8fc54bda028d574022e8231a3b684c177c2d35da75802ff78d4f4e`

## Import List
- KERNEL32.DLL: 68 imports (all resolved)
- msvcrt.dll: 94 imports (all resolved)
- **Total: 162 resolved, 0 unresolved**

## Runtime Trace Summary
1. PE loaded at 0x400000, EP=0x4014f0, 10 sections
2. All 162 imports resolved successfully
3. TLS initialized, _initterm callbacks ran
4. CRT startup completed (malloc/calloc/printf working)
5. `RaiseException(code=0x20474343)` — **GCC C++ exception**
6. VEH handler at 0x49c9c0 called, returned 0 (EXCEPTION_CONTINUE_SEARCH)
7. .pdata handler lookup failed (malformed unwind data)
8. Second `RaiseException(code=0x20474343)`
9. `abort()` → SIGABRT

## Failure Location
- **Signal:** 6 (SIGABRT) at RIP=0x7f91eaac095c (glibc abort)
- **Root cause:** UPX uses GCC C++ exception handling. Exception code `0x20474343` is the GCC exception class ("GCC" reversed = `CCG ` = 0x20474343).

## Missing Behavior
1. **GCC _Unwind_RaiseException not implemented** — UPX throws C++ exceptions via `RaiseException` with GCC exception class. The VEH handler (UPX's own) returns `EXCEPTION_CONTINUE_SEARCH` because it expects a proper CONTEXT record.
2. **RaiseException passes NULL CONTEXT** — Our `mw_RaiseException` builds an EXCEPTION_POINTERS with `CONTEXT* = NULL`, but the VEH handler needs context to unwind.
3. **__C_specific_handler is a no-op** — Returns 0 (CONTINUE_SEARCH) without actually walking the __try/__except chain.
4. **No CxxThrowException / _CxxThrowException support** — GCC uses a different exception mechanism than MSVC.

## Expected Behavior
On Windows:
- `RaiseException(0x20474343, ...)` triggers the VEH handler
- The VEH handler calls `_Unwind_RaiseException` (GCC personality)
- The personality routine walks the call stack using .xdata/.pdata
- The appropriate catch handler runs
- UPX prints version info and exits normally

## Root Cause
UPX was compiled with **MinGW/GCC**, not MSVC. It uses **GCC exception handling** (Itanium C++ ABI / DWARF unwind), not MSVC SEH. The `RaiseException` call is a thin wrapper that the GCC runtime uses to trigger exception propagation.

Our loader:
1. Does not implement `_Unwind_RaiseException` or the GCC personality routine
2. Passes NULL context to VEH handlers
3. Has a no-op `__C_specific_handler`

## Fix Plan
### Option A: Implement minimal GCC unwinding (correct but complex)
- Implement `_Unwind_RaiseException`, `_Unwind_Find_FDE`, `_Unwind_GetCFA`
- Parse .eh_frame / .xdata for DWARF unwind info
- Very complex, ~500+ lines

### Option B: Catch the specific exception and continue (minimal, evidence-driven)
- In `RaiseException`, detect GCC exception class (0x20474343)
- For `--version` mode, UPX throws exceptions during option processing when it encounters "unexpected" conditions
- Instead of crashing, log and continue
- The VEH handler needs a valid CONTEXT to work

### Option C: Build a minimal _Unwind_Backtrace (middle ground)
- Implement enough of libgcc_s unwind to walk the stack
- Let UPX's own exception handlers run
- ~200 lines

**Decision:** Start with Option B (evidence-driven per RULE 1), measure what happens, then upgrade to Option C if needed.
