# BUG-058 — ReadFile/WriteFile ignored OVERLAPPED offsets

**Status:** CLOSED (TESTED) — 2026-10-17, wave W4
**Found by:** sqlite3 reopen of its own freshly-created DB failed with
SQLITE_NOTADB (26) although the on-disk file was byte-perfect
**Files:** src/loader/loader.c

## Root cause
Guests issue positioned I/O as ReadFile(h, buf, n, out, OVERLAPPED*) with
the offset inside the OVERLAPPED (sqlite3's winRead never calls
SetFilePointer for these). Our bridge ignored the 5th argument and read at
the sequential fd position: after the 100-byte header sniff the fd sat at
offset 100, so every page read was shifted — the schema parse saw garbage
and reported "file is not a database" on a byte-perfect file.

## Fix
When overlapped != NULL, ReadFile/WriteFile use pread/pwrite at
OVERLAPPED.Offset/OffsetHigh (x64 layout: offset at +16) and leave the
sequential position untouched; NULL overlapped keeps read/write semantics.

## Verification
sqlite3 file DB create + select round trip 3/3; integrity via SELECT.
