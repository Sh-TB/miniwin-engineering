# BUG-057 — WideCharToMultiByte fixed-length path used 4-byte wchars

**Status:** CLOSED (TESTED) — 2026-10-17, wave W4
**Found by:** sqlite3 "unable to open database: out of memory"
**Files:** src/loader/loader.c

## Root cause
WCTMB with srclen>=0 and cp != 65001 fell through to `wcsnrtombs`, which
reads 4-byte glibc wchars — guest data is 2-byte UTF-16LE → EILSEQ → error
1113 on every fixed-length conversion. sqlite's winFullPathname conversion
failed and surfaced as SQLITE_NOMEM.

Also closed in the same wave:
- remaining 5 `wcstombs` guest-side sites (GetFullPathNameW among them —
  its input was mojibake, so GetFullPathNameW returned "/tmp/x/<garbage>")
- LoadLibrary family: known system DLLs + api-ms-win-* API sets now succeed
  with pseudo-handles (GetProcAddress resolves by NAME from the dispatch
  table; unknown optional extensions resolve to a generic ms_abi stub);
  unknown DLLs still fail with ERROR 126
- GetModuleHandleExW by-name succeeds for system modules
- InitializeCriticalSectionEx implemented for real

## Verification
sqlite3 create/insert/select round trip on a file DB, 3/3 deterministic.
