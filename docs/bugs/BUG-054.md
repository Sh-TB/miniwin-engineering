# BUG-054 — Guest path separators: backslash paths reached POSIX unnormalized

**Status:** CLOSED (TESTED) — 2026-10-17, wave W3
**Found by:** 7za.exe `x` (extract) — "Cannot open the file as archive"
**Files:** src/loader/loader.c (w3_normalize_path + W path APIs)

## Root cause
`GetCurrentDirectoryW` returns the POSIX cwd (`/tmp/z7t`); 7-Zip (like any
Windows program) appends `\`-separated components → the guest passes
`/tmp/z7t\test.7z` back into the W file APIs. `find_first_impl` split
directories on `/` only, so the pattern became `\test.7z` → no match →
ERROR_FILE_NOT_FOUND → 7za reported "Cannot open the file as archive"
(trace line: `FindFirstFile(/tmp/z7t\test.7z)`).

## Fix
`w3_normalize_path()`: in-place `\`→`/`, strip a single-letter drive prefix
(`C:` → `/`), collapse duplicate slashes. Applied in the W path APIs:
find_first_impl, w3_create_file, _wopen, SetCurrentDirectoryW,
GetTempFileNameW, MoveFileExW, CopyFile2, _wrename, MoveFileW(+Progress),
GetFileAttributesW-family buffers (f8/t8/l8/r8/a8/b8 blanket pass).

## Verification
- 7za extract of the loader-created archive: exit 0, extracted files
  SHA-256-identical to the originals ("ROUND-TRIP OK"), 3/3 deterministic.
- G1 PIN OK; regression 12/12; t13_wide_abi PASS.

## BUG-054b (2026-10-17) — absolute backslash paths on the WRITE side too
CONTINUE #9 registered the frontier: `7z e final.7z -o\tmp\7ztest\out` produced a
literal backslash-named directory in the CWD. Root cause: `w3_normalize_path` was
applied to CreateFileW/_wopen/MoveFileExW/CopyFile2/GetTempFileNameW/
SetCurrentDirectoryW but NOT to the directory/delete/attributes family.
Fixed (same one-line rule): CreateDirectoryW, RemoveDirectoryW, DeleteFileW,
GetDiskFreeSpaceExW.
Verification: scripts/bug054b_accept.sh — `7za e final.7z "-o\\tmp\\7ztest54b\\out"`
→ exit 0, output at the normalized POSIX path, SHA-256 byte-perfect, no stray
backslash-named directory, 3/3 deterministic (evidence/master/bug054b/20261017_130230).
