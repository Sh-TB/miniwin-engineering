# BUG-056 — GetStdHandle returned handles unknown to the file-handle registry

**Status:** CLOSED (TESTED) — 2026-10-17, wave W4
**Found by:** sqlite3.exe (every CLI output silently lost)
**Files:** src/loader/loader.c

## Root cause
`GetStdHandle(-10/-11/-12)` returned bare pseudo-handles 0xa/0xb/0xc.
`w3fd_from_handle` expects 4+idx registry handles; the legacy fallback in
Read/WriteFile only mapped 4/8/0xC, so stdout (0xb) writes failed with
"invalid handle" while stderr (0xC) worked by accident. sqlite3 executes
SQL normally (exit codes prove it) but its entire output surface vanished.

## Fix
GetStdHandle now registers fds 0/1/2 in the w3file registry and returns
those handles; all consumers (ReadFile/WriteFile/GetConsoleMode/SetStdHandle)
share one identity space. Implemented as mw_GetStdHandle_impl next to the
registry with a forward-call shim at the original site.

## Verification
sqlite3 --version prints the full 3.50.4 banner; SELECT/INSERT round trip
works (evidence/master/opensrc-battery/).
