# BUG-035 — callback function pointers invoked SysV-side keep ms_abi expectations

**Status:** CLOSED (TESTED, 2026-10-15, EXP-040)
**Priority:** P0 (any glibc-side callback)
**Discovered:** appcompat sweep (t04 SIGSEGV inside the qsort comparator)

## Symptom

t04 crashed at RVA 0x1740: `mov eax,[rcx]; cmp eax,[rdx]` with RCX=0, RDX=0 —
the PE's `cmp_int` comparator dereferenced NULL. R9 = 0x140001740 = the
comparator itself (glibc qsort's indirect call target).

## Root cause

`mw_qsort` passed the PE's ms_abi comparator pointer directly to glibc
`qsort`. glibc invokes it SysV-style (args in RDI, RSI); the ms_abi callee
expects them in RCX, RDX → reads register garbage (here zeros) and faults.
Same latent class: glibc-invoked callbacks of every kind (signal handlers,
atexit handlers are arg-less and thus ABI-lucky, thread start routines).

## Fix

`qsort_r` bridge (loader.c BUG-035 block):
```c
typedef int (__attribute__((ms_abi)) *mw_ms_qsort_cmp)(const void*, const void*);
static int mw_ms_qsort_bridge(const void* a, const void* b, void* ctx) {
    return (*g_ms_qsort_cmp_ref)(a, b);   /* ms_abi indirect call: GCC emits RCX/RDX */
}
mw_qsort: g_ms_qsort_cmp_ref = &cmp; qsort_r(base, n, sz, bridge, NULL);
```
The bridge is SysV (glibc-safe); the re-dispatch through an ms_abi-typed
function pointer makes GCC translate the register mapping. Single-threaded
comparator slot (documented limitation — threaded qsort not exercised).
