# BUG-061 — `_stat64` MS x64 layout wrong + 128-byte memset overflow (zstd crash RIP=0x0)

**Status:** CLOSED (TESTED) 2026-10-17. **Found by:** LADDER-008 (zstd.exe 1.5.6, mingw/msvcrt).

## Evidence
- `zstd.exe payload.txt` → exit 139, `[CRASH] Signal 11 at RIP=0x0`, RAX=0xffffffffffffffff,
  RBP=0x0, RIP outside PE and outside loader mappings; deterministic 3/3.
- api_trace.json last event before crash: `_stat64(path=payload.txt)` (all other
  zstd imports had been implemented in the same wave: FindFirstFileA/FindNextFileA,
  SetPriorityClass, _filelengthi64, fgetpos, fsetpos, SleepConditionVariableCS).

## Root cause (two defects in one function, `mw__stat64` ~L4230)
1. **Wrong struct layout**: the guest `struct _stat64` (MS x64) is 56 bytes —
   `dev@0 u32, ino@4 u16, mode@6 u16, nlink@8 u16, uid@10, gid@12, rdev@16 u32,
   size@24 i64, atime@32, mtime@40, ctime@48`. We wrote POSIX-ish offsets
   (mode@0, size@8, times @24/32/40) → zstd read `st_size` from offset 24 and
   got an epoch-time garbage size.
2. **Buffer overflow**: `memset(st, 0, 128)` wrote 72 bytes past the 56-byte
   guest struct, corrupting adjacent guest memory (global/stack neighbors) —
   the actual RIP=0x0 mechanism.

## Fix
Exact MS layout writer + `memset(st, 0, 56)`. Sibling `_wstat64i32` variant is
separate (i32 size) and was not implicated; audit pending as BUG-061 follow-up note.

## Verification
- zstd compress: exit 0, `payload.txt : 119.12% (68 B => 81 B, payload.txt.zst)`.
- zstd decompress: exit 0; SHA-256 byte-perfect round trip; **3/3 deterministic**.
- Regression 12/12; G1 pin OK (evidence/master/g1/20261017_131102).
