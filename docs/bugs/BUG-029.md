# BUG-029 — terminate → abort after a CORRECT landing-pad resume (catch machinery)

**Status:** CLOSED — ROOT-CAUSE ISOLATED & SUPERSEDED (2026-10-15, EXP-038). The EH_FIX
dispatch-1 hijack was the poison (candidate 1 confirmed): with both hacks flag-guarded OFF
(TASK-API-005/ADR-010), the flow is a single clean dispatch with no re-raise chain and no
'unsigned long long' machinery — the frontier moved to the PE's own dt_check assertion.
The remaining failure decomposed into **BUG-030** (selector not delivered in RDX — fixed)
and **BUG-031** (intermediate-frame cleanup chain — open, next task).
**Priority:** P0 (acceptance path blocker — current frontier)
**Discovered:** 2026-10-14, post-BUG-027 live trace (EXP-037 §4.2/§5)

## Symptom
With the landing pad 0x4dcd24 resumed at the correct throw-site RSP
(alloc_total=0x48, RSP=est−0x48) and RAX=exception object, execution runs the
catch/protocol machinery (TlsGetValue/SetLastError/GetLastError sequence) and
then invokes terminate → abort. stdout: `terminate called after throwing an
instance of 'unsigned long long'`. Exit 134. No second RtlDispatchException
appears in the trace (no new RaiseException) — terminate fires while the
original exception is still in flight.

## Context (what changed)
- pre-BUG-026: exit 134, dispatch walk never started.
- post-BUG-026: exit 139, landing pad resumed with RSP+8 → SIGSEGV.
- post-BUG-027: exit 134 at a STRICTLY LATER verified point: correct resume,
  catch TLS calls run, terminate during catch processing.

## Root-cause candidates (ordered, to be tested in this order)
1. **EH_FIX dispatch-1 interference (top suspect — also an engineering-rules
   violation standing on its own).** Dispatch-1's personality legitimately
   returned ContinueSearch; EH_FIX (loader.c L~1607-1644) force-resumed the PE
   at LP 0x401573, which built the 'unsigned long long' exception machinery and
   re-raised via the helper chain (dispatch-2 from RIP=0x49d5b1). The GCC
   `__cxa`/TLS exception state is thereby poisoned before dispatch-2's catch
   runs. On Windows the flow would be: dispatch-1 → GCC core → site A →
   RtlUnwindEx → landing pad (no re-raise chain, no terminate).
   **Action: TASK-API-005 — isolate EH_FIX (+CXX-EH-FIX) behind
   `MINWIN_EH_HACKS`, default OFF — then re-run.**
2. GCC-core input dependency: the core reads `disp->ContextRecord->Rsp`; our
   dispatcher passes the post-unwind `est` where Windows passes the pre-unwind
   throw-site RSP. May affect the INSTALL decision on dispatch-1.
   **Action if (1) insufficient: pass the pre-unwind context to the handler
   (dispatcher change; was outside BUG-027's boundary).**
3. Site B/C of the personality (0x21474343 re-raise protocol, RtlUnwindEx
   arg3=real CONTEXT there) — not yet exercised; audit after (1)/(2).
