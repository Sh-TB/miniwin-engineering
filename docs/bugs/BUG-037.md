# BUG-037 — unwind-code interpreter faults on CRT-startup UNWIND_INFO (FPREG/XMM path)

**Status:** OPEN (REGISTERED 2026-10-15, EXP-040) — next task
**Priority:** P0 (blocks C++ EH = t08; acceptance G2)
**Discovered:** appcompat sweep, t08 first C++ throw after TASK-TLS-001

## Symptom

t08 (C++17, static libc++) reaches main, runs STL code, throws the first
`NotFound`; the dispatcher walks and the personality runs (trace: handler
called, `disposition=1 ContinueSearch`, frames 2→3 walked correctly) — then
the loader itself faults:

```
[CRASH] Signal 11 at RIP=0x201190b   (inside seh_internal_virtual_unwind)
  RAX=0x78 RCX=0x1470 RDX=0x140001c84 R9=0x27
  [DISPATCH] Frame[3]: RIP=0x140001c84 RVA=0x1c84 CTX.Rsp=0x7ffe0797d8a0
  [DISPATCH] Frame[3]: RF begin=0x1470 end=0x23d9 ui=0x50458
```

Faulting instruction: `mov (%r9),%rbx` in the UWOP_SAVE_NONVOL handler —
R9=0x27 is a **raw stack-slot offset** where a stack **address** was
expected. RAX=0x78 = the CONTEXT field offset it tried to store to.

## Ground truth (frame in question)

- RF: begin=0x1470 end=0x23d9 (mingw CRT startup `mainCRTStartup` region),
  UNWIND_INFO at RVA 0x50458 (file off 0x4ea58):
  version=1, flags=0x03 (UNW_FLAG_EHANDLER|UNW_FLAG_UHANDLER),
  prologue size=34, code count=13, frame byte=0x85 (FP reg 5=RBP),
  personality RVA=0x131b0.
- Codes include SET_FPREG (0x03) / SAVE_XMM128 (0x08) class structures the
  UPX frames never exercised; a naive sequential or reverse slot walk
  misaligns on this array (manual decodes in EXP-040 §bug037 notes both
  attempts, confirming the interleave needs a reference-quality decoder).
- With R9 poisoned (0x27), the save handler dereferences a near-NULL
  address → SIGSEGV in the loader.

## Working hypothesis (to verify first, per protocol)

The interpreter advances the stack cursor into a variable for one opcode
family but enters the save handler with the raw slot index when the code
array is scanned with the **prologue_size=34 > count*2 interleave** (epilogue
blob or chained-info handling) — i.e. an ordering/alignment edge in the
reverse slot walk that UPX's simple frames (PUSH/ALLOC_SMALL only) could not
expose.

## Fix plan (TASK-BUG-037)

1. Write a standalone reference decoder (Python) for UNWIND_INFO with
   version/flags/prologue-epilogue rules; pin the exact slot sequence of
   RVA 0x50458 as a golden test vector (add to tests/).
2. Align the loader interpreter's cursor bookkeeping with that vector
   (SET_FPREG establishes the FP baseline — FP-relative saves use it;
   SAVE_XMM128 consumes 16-byte slots; UWOP_EPILOGUE (0x06) is
   version>=2-only and must not be decoded as v1).
3. Re-run t08 → expect the throw to reach `catch (NotFound)` and the suite
   to PASS (18+ checks); regression 12/12 + G1 gate.
4. Then C++ EH acceptance (G2) can be evaluated for real.
