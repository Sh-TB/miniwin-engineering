# BUG-037 — unwind-code interpreter faults on CRT-startup UNWIND_INFO (FPREG/XMM path)

**Status:** CLOSED TESTED (2026-10-15, CONTINUE #7)
**Priority:** P0 (blocked C++ EH = t08; acceptance G2)
**Discovered:** appcompat sweep, t08 first C++ throw after TASK-TLS-001
**Closed by:** three spec-level fixes in the opcode layer (EXP-041)

## Symptom (original)

t08 (C++17, static libc++) reached main, ran STL code, threw the first
`NotFound`; the dispatcher walked frames 2→3 and the loader faulted:

```
[CRASH] Signal 11 at RIP=0x201190b   (inside seh_internal_virtual_unwind)
  RAX=0x78 RCX=0x1470 RDX=0x140001c84 R9=0x27
```

Faulting instruction `mov (%r9),%rbx` in the UWOP_PUSH_NONVOL handler with
R9=0x27 — a garbage simulated RSP.

## Root cause — THREE stacked defects (all ours, none in the binaries)

1. **Outdated opcode numbering** (`include/pe.h`, `src/pe/pe.h`): the loader
   used `UWOP_SAVE_XMM128=6/7, UWOP_PUSH_MACHFRAME=8` — the deprecated
   pre-release values. The current Microsoft PE/COFF x64 spec (and LLVM
   Win64EH.h, .NET win64unwind.h, radare2, ReactOS with migration comments)
   define `6=UWOP_EPILOG(v2), 7=UWOP_SPARE_CODE, 8=UWOP_SAVE_XMM128,
   9=UWOP_SAVE_XMM128_FAR, 10=UWOP_PUSH_MACHFRAME`. Every modern toolchain's
   XMM spill (op 8) therefore decoded as a machine frame: `new_rsp += 40`
   plus a stack read that replaced the simulated RSP with junk (0x1f → +8 =
   0x27 fault address).
2. **CountOfCodes semantics**: it counts SLOTS (code words + operand slots —
   MS doc: "UWOP_ALLOC_LARGE (1) 2 or 3 nodes"; ReactOS advances its cursor
   by `UnwindOpSlots()`). All five loader decode loops bounded on the code
   index instead, so padding and the handler RVA decoded as phantom codes.
   Reproduced standalone: t08 CRT frame (count=13, 13 slots) yielded
   `alloc_total=0xff0191` by reading the handler RVA (0x131b0) as
   ALLOC_LARGE u32; correct value = **0x188**.
3. **Frame-register nibbles swapped**: UNWIND_INFO byte 3 is little-endian
   C bitfields — `FrameRegister` is the LOW nibble, scaled `FrameOffset` the
   HIGH nibble (winnt.h `UCHAR FrameRegister:4; UCHAR FrameOffset:4;`).
   mingw's `lea rbp,[rsp+0x80]` encodes byte 0x85 = RBP(5)/off(8); the old
   decode read FP=R8/off=5.

## Fixes (all in this repo)

- `include/pe.h` + `src/pe/pe.h`: renumbered opcodes, added UWOP_EPILOG(6),
  UWOP_SPARE_CODE(7), UWOP_SAVE_XMM128(8), UWOP_SAVE_XMM128_FAR(9),
  UWOP_PUSH_MACHFRAME(10), with source citations.
- `src/loader/loader.c`: new shared `seh_unwind_op_slots(op, info)` helper;
  all five decode loops (chained + main in seh_internal_virtual_unwind,
  seh_total_prologue_alloc, mw_RtlUnwindEx target-alloc loop,
  mw_RtlVirtualUnwind) now bound on the slot cursor, skip un-executed codes
  with FULL operand-slot advance, handle EPILOG (v2-only; v1 = stop decode),
  SPARE, and the renumbered ops; SET_FPREG re-anchors RSP from the LIVE FP
  register minus FrameOffset*16 (ReactOS semantics); frame nibble fixed at
  all three read sites; missing UWOP_SAVE_NONVOL slot advance added to the
  target-alloc loop; its ALLOC_LARGE info==1 decode made unscaled (API-006
  rule) — the last copy still carrying the deviation; FP-frame resume RSP
  in mw_RtlUnwindEx = `tgt_frame - FrameOffset*16` (body RSP) instead of
  `tgt_frame - alloc_total`.

## Verification

- Golden vector: t08 CRT-startup UI (RVA 0x50458) decode pinned by
  `scripts/bug037_ref_decode.py` + `scripts/bug037_lsda_parse.py`
  (13 slots, descending END-offsets, handler 0x131b0 at +32).
- Standalone harness `scripts/bug037_alloc_harness.c` reproduced
  alloc_total=0xff0191 pre-fix and now yields 0x188.
- Regression **12/12**, UPX G1 gate **exit 0** (3 pins this session:
  evidence/master/g1/20261015_{063340,064317,073727}).
- t08 no longer faults in the interpreter: the full 4-frame walk completes,
  the intermediate cleanup walk runs, and the resume is attempted with the
  correct body RSP — the remaining failure is a NEW, distinct bug
  (**BUG-038**: landing-pad placeholder, see BUG-038.md).
- Sweep **10/12 PASS** (t01-t07 + new t10/t11/t12), up from 7/9.
