7. CRITICAL BUG: UNWIND_INFO INTEGRITY
================================================================

The function at 0x9d560 has 'sub rsp, 0x28' but its UNWIND_INFO
lacks an ALLOC_SMALL opcode. This means:

  1. RtlVirtualUnwind will NOT undo the 'sub rsp, 0x28'
  2. The establisher frame will be WRONG
  3. The parent RIP read from [establisher_frame] will be WRONG

This is the ROOT CAUSE of the failed stack walk.

HYPOTHESIS: This function is a UPX-generated wrapper that was
compiled with minimal unwind info (perhaps /Oy or similar).
The function is small enough that the compiler decided to not
fully describe the prolog.

RESOLUTION PATH: The exception dispatcher must be robust against
incomplete UNWIND_INFO. For the specific case of RaiseException,
the CONTEXT.Rsp is known exactly (from the naked stub), so we
can bypass the first frame's unwind entirely and start the stack
walk from the caller's caller.

2. For the FIRST frame (RaiseException caller), skip the unwind

9. ABI NOTE: ms_abi vs SysV
================================================================

When calling ms_abi functions (mw_RtlLookupFunctionEntry,
mw_RtlVirtualUnwind) from our own code, we MUST use ABI shim
functions or inline the logic. Direct calls from SysV code to
ms_abi functions cause XMM alignment crashes (movaps on
unaligned RSP).

Solution: Internal SysV-only copies of the lookup/unwind logic
(seh_internal_lookup) for use within the dispatcher.
